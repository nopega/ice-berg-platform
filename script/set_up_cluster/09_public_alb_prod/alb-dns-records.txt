; Public hostnames pointing at the shared ALB.

; ALB: k8s-dataplatformpubli-be0fb7e6a4-515848705.ap-southeast-1.elb.amazonaws.com
;
; HOW TO IMPORT
;   Cloudflare -> nopega.net -> DNS -> Records -> Import
;   Leave "Proxy imported DNS records" UNCHECKED.
;
; WHY DNS-ONLY AND NOT PROXIED
;   1. The ALB serves an ACM certificate issued for these exact names. Proxying
;      puts Cloudflare's certificate in front instead and adds a second TLS hop
;      that has to be configured correctly or it fails as a 5xx that looks like
;      the origin is down.
;   2. Cloudflare's free plan caps request bodies at 100 MB -- invisible for
;      Airflow, fatal for pushing a container image layer. harbor.nopega.net
;      will use this same ALB for that reason, so the zone stays consistent.
;
; A CNAME is used rather than an A record because an ALB's IP addresses change
; without notice. Pinning an IP works until AWS replaces a node, then fails.
;
; All four point at the same ALB. That is the point of the shared
; group.name: one load balancer, one certificate, one bill, four hostnames
; routed by host rule.
;
; Cloudflare reports anything already present as a duplicate and skips it, so
; re-importing this whole file is safe -- only the new row takes effect.
;
; IMPORT THIS ONE ONLY AFTER THE INGRESS EXISTS.
; The ALB hostname above is created by ./02_apply_public_ingress_prod.sh, and
; grafana's rule only appears once the monitoring stack is installed, since the
; Ingress names a Service (kube-prometheus-stack-grafana) that has to exist for
; the target group to become healthy. Pointing DNS at the ALB before then
; resolves correctly and returns 503, which reads like a broken deployment
; rather than an ordering mistake.
